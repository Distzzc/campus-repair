# 测试与完成规范

读取时机：任何实现、测试或验证记录前。当前全部适用；未来业务测试在对应变更添加。

1. 从Requirement/Scenario生成用例；测试名或注释写Scenario ID；正常/失败/边界均覆盖，具体映射见 `docs/verification/scenario-matrix.md`。遗漏Scenario且无文档检查证据即缺陷。
2. 每例tmp_path创建独立库，清理APP_ENV/DATABASE_PATH等主机环境，不读取真实.env、不挂载生产卷。使用真实库验证健康查询，并用受控故障验证异常。污染真实数据即缺陷。
3. 本地 `python -m pytest -q`；容器 `docker compose --env-file .env run --rm --no-deps test`。非零退出、意外跳过或必需验证未执行均阻断完成；不得把静态检查冒充运行成功。
4. 修改行为同步更新specs、tests、README和映射。任务只有实际验收通过才勾选；证据包含日期、平台/版本、命令、退出码、结果、限制，存 `docs/verification/`。
5. 完成定义：实现、测试、规约、文档一致；所有当前必需验证通过；无真实敏感数据；未实现的后续能力仍写待实现/待验证。虚构通过/异机评审即缺陷。
6. 规范测评：先在隔离副本故意引入反向导入或错误函数命名，运行治理检查必须失败；移除后通过。新会话实验需要真正另起会话且保存输入、修改与结果，不能用同会话重复测试冒充。

跨机器peer review由组内另一位成员用自己的机器完整复现；记录操作者、机器、代码版本、命令和结果。尚未执行则待验证，不属于本机自动化测试的替代结果。
