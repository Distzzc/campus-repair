# 产品规范

读取时机：需求、术语、页面、状态和表单设计前。当前仅固化产品边界；以下业务/页面规则均为后续阶段，尚未实现/验证。

项目名称为“校园报修与 AI 工单辅助系统”。学生提交报修、查本人记录、补充信息、允许阶段取消、确认并评价；管理员查全部、改分类/优先级、分配和统计；维修人员查获派工单、接单、加处理记录、交结果。

工单指一次报修及完整历史；负责人指当前获派维修人员；处理记录是维修补充内容；状态记录是不可覆盖审计。保留提交人、地点、原始及整理后描述、分类、附件、负责人、状态、创建/更新时间。每次状态变化原子追加操作人、时间、前后状态和说明。

| 操作人/动作 | 起始状态 | 目标状态 |
| --- | --- | --- |
| 学生提交 | 新报修 | 待分配 |
| 管理员分配 | 待分配 | 待接单 |
| 获派维修人员接单 | 待接单 | 处理中 |
| 获派维修人员提交结果 | 处理中 | 待确认 |
| 学生确认 | 待确认 | 已完成 |
| 学生反馈未解决 | 待确认 | 处理中（保留负责人） |
| 学生取消本人报修 | 待分配/待接单 | 已取消 |

已完成/已取消为终态；其余转换拒绝；补充信息不改变状态；重新分配等扩展另提变更。评价和确认仅本人可操作。

未来页面：登录/无权限页；学生报修表、个人列表、详情/补充/确认；管理员工作台、详情/分配、统计；维修任务列表、处理详情。每个页面必须定义加载/正常/错误/空状态；表单定义必填/类型/长度/边界及前后端同一校验规则；错误可恢复且保留输入。字段长度等具体业务参数必须在对应提案确定，不能实现时临时猜测。

检查方法/缺陷判据：当前审阅角色、术语、页面四态、状态表和路线图齐备；后续逐页检查四态/表单边界、按上表正向和非法转换参数化测试、越权测试。遗漏四态、丢输入、允许越权/非法转换或覆盖历史均为缺陷。

独立变更顺序：登录权限→学生报修查询→分配处理→确认评价附件→AI整理分类→统计及可选相似历史检索。当前只建工程骨架，不提前实现这些功能。
